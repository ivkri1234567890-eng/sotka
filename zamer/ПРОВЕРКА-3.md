Основной сценарий 3.0 выполнен в Edge и в Playwright WebKit под Windows с сенсорным мобильным окном. Доступ к сети браузера отключался после первоначального кеширования и до открытия импортёра. Для тестов использовался отдельный профиль с искусственными проектами. Физические телефоны, нативный Bluetooth и установка APK в эти результаты не входят.

## Повторение

Из каталога с приложением и файлами `gate.js`, `hub.js` установите тестовую библиотеку командой `python -m pip install playwright`, затем движки командой `python -m playwright install chromium webkit`. В PowerShell:

```powershell
python zamer/tests/media_roundtrip.py
python zamer/tests/review_3.py
$env:ZAMER_ENGINE = 'webkit'
python zamer/tests/review_3.py
Remove-Item Env:ZAMER_ENGINE
python zamer/tests/offline_update.py ПУТЬ_К_ПРЕЖНЕМУ_ВЕБ_АРХИВУ.zip
```

Для проверки действующим Edge укажите путь к `msedge.exe` в переменной `ZAMER_CHROMIUM`. Для независимой проверки CAD установите `ifcopenshell` и `ezdxf`, задайте `ZAMER_VERIFY_CAD=1` и повторите `review_3.py`. Предыдущий веб-архив для теста обновления должен содержать пути `sotka/gate.js`, `sotka/hub.js` и `sotka/zamer/`. Репозиторий позволяет получить веб-базу 2.9 командой `git archive --format=zip --prefix=sotka/ -o base-2.9.zip 79abc50 gate.js hub.js zamer`.

## Что проверить на телефонах

1. На iPhone открыть согласованный тестовый HTTPS-адрес в Safari. Проверить выбор исходного PDF через «Файлы», JPG через медиатеку, сохранение ZIP в «Файлы» и повторное открытие после ухода Safari в фон.
2. На Redmi 15C в браузере выполнить тот же сценарий. После получения полной нативной сборки отдельно проверить установку обновления поверх рабочей версии с сохранением данных, выбор фотографий и сохранение ZIP через системный диалог.
3. Подключить используемый дальномер. Записать два известных эталонных расстояния в карточку стены и инженерную карточку. Проверить выбранные единицы, смену активного поля, отключение и повторное соединение. Для iPhone предусмотрен ручной ввод.
4. Взять копию реального плана с диагональными стенами и несколькими контрольными размерами. Сравнить длины и высоты на 2D, развёртке, в PDF и в используемой CAD. Для больших проектов проверить экспорт на устройстве с наименьшим объёмом памяти.

## Ограничения

- Это полуавтоматический обмер. Фотография в перспективе может иметь разный масштаб по сторонам. Поворот и контроль нескольких длин помогают обнаружить искажение. Для сильно искажённого фото потребуется прямой скан или повторная съёмка.
- Для ASCII DXF поддержаны LINE, POLYLINE, LWPOLYLINE, подписи и доступные числовые размеры. Неподдерживаемые объекты, в том числе блоки и дуговые полилинии, перечисляются в предупреждении. Их следует разложить на линии в CAD. Сложные векторные PDF и малоконтрастные сканы могут потребовать ручной обводки. Точки проёмов по подписи и слою всегда требуют проверки.
- OCR ищет числовые размеры. Названия комнат, высоты и этажи подтверждает замерщик. Листы с разным началом координат на одном этаже следует совместить в обычном редакторе общего плана.
- Большие фотоальбомы всё ещё зависят от доступной памяти устройства. Оригиналы фото могут быть доступны только как файл, если браузер не понимает их кодек. Размер входного чертежа ограничен 32 МиБ, суммарный размер ZIP — 256 МиБ.
- В исследованных архивах Android 2.4 и 2.5 найден только отдельный Glm.java, в 2.6 и в текущей папке Android на GitHub — готовые сборки. Для воспроизводимой сборки 3.0 необходим проект оболочки 2.9 Fixed с Activity, мостами Bluetooth/файлов, манифестом и конфигурацией сборки.
